# 02 · 6502 CPU：寄存器、寻址、周期与中断

> NES 的 CPU 是 Ricoh 2A03，内部为 MOS 6502 内核。理解 6502 是理解
> “游戏代码如何逐周期运行”的起点。

## 1. 一个非常小的 CPU

6502 于 1975 年推出，设计目标是廉价、简单、足够快。它只有：

- 8 位数据总线、16 位地址总线；
- 约 3,510 个晶体管（NMOS 版）；
- 56 条官方指令、13 种寻址方式；
- 没有乘法、除法、浮点，也没有通用寄存器堆。

NES 中的 2A03 是定制版：

- 去掉十进制模式（BCD）；
- 时钟 1.789773 MHz（NTSC）；
- 片内集成 APU 和手柄接口。

## 2. 寄存器

| 寄存器 | 宽度 | 作用 |
|---|---|---|
| A | 8 位 | 累加器，算术/逻辑/数据传输的中心 |
| X | 8 位 | 变址寄存器，也常用于循环计数 |
| Y | 8 位 | 变址寄存器 |
| SP | 8 位 | 栈指针，实际栈地址为 `$0100 + SP` |
| PC | 16 位 | 程序计数器 |
| P | 8 位 | 状态寄存器 |

状态寄存器位：

```text
bit 7  N  Negative   结果 bit7
bit 6  V  Overflow   有符号溢出
bit 5  -  未使用，恒为 1
bit 4  B  Break     不是真实位，只出现在压栈副本
bit 3  D  Decimal   NES 2A03 忽略
bit 2  I  IRQ 屏蔽
bit 1  Z  Zero      结果是否为 0
bit 0  C  Carry     进位/无借位/移位输出
```

CPU 寄存器实现位于
[`Cpu6502.cs`](../src/NesEmulator.Core/Cpu/Cpu6502.cs)：

```csharp
public byte A { get; private set; }
public byte X { get; private set; }
public byte Y { get; private set; }
public byte SP { get; private set; }
public ushort PC { get; private set; }
public byte P => (byte)(_status | (byte)CpuFlags.Unused);
```

`B` 不作为真实状态保存。`PHP`/`BRK` 压栈时强行置 `B=1`；`IRQ`/`NMI` 压栈时清 `B`。
这是很多模拟器容易写错的地方。

## 3. 地址空间与零页

CPU 的 16 位地址空间由主板译码，详见
[`01-NES架构总览.md`](01-NES架构总览.md)。对 CPU 来说最重要的是：

- `$0000-$00FF` 是**零页**：地址只占 1 字节，指令更短、执行更快；
- `$0100-$01FF` 是栈页；
- `$8000-$FFFF` 通常映射卡带的 PRG-ROM。

零页索引寻址会在 `$00-$FF` 内回绕。例如 `LDA $FF,X` 且 `X=1` 时，真实地址是
`$00` 而不是 `$0100`。代码中通过强制转换为 `byte` 实现：

```csharp
byte address = (byte)(FetchByte() + X);
```

同样，`(zp,X)` 的指针加法、`(zp),Y` 的指针高字节读取也都在零页内回绕。

## 4. 寻址方式

| 模式 | 示例 | 操作数字节 | 含义 |
|---|---|---|---|
| 隐含 Implied | `CLC` | 0 | 操作数隐含在指令中 |
| 累加器 Accumulator | `ASL A` | 0 | 操作 A |
| 立即 Immediate | `LDA #$10` | 1 | 操作数就是下一字节 |
| 零页 ZeroPage | `LDA $10` | 1 | 地址 `$0010` |
| 零页 X | `LDA $10,X` | 1 | `($10+X) & $FF` |
| 零页 Y | `LDX $10,Y` | 1 | `($10+Y) & $FF` |
| 绝对 Absolute | `LDA $1234` | 2 | 小端 16 位地址 |
| 绝对 X | `LDA $1234,X` | 2 | `$1234+X`，读指令可能跨页 +1 |
| 绝对 Y | `LDA $1234,Y` | 2 | `$1234+Y` |
| 间接 Indirect | `JMP ($1234)` | 2 | 仅 JMP 使用，含页边界 bug |
| `(zp,X)` | `LDA ($10,X)` | 1 | 零页指针加 X 后再解引用 |
| `(zp),Y` | `LDA ($10),Y` | 1 | 零页指针解引用后加 Y |
| 相对 Relative | `BNE label` | 1 | 有符号 8 位偏移，用于分支 |

实现分两条路径：

- 读指令使用 `ReadOperand()`，同时返回有效地址、值和“是否跨页”；
- 写指令使用 `ResolveAddress()`，**不读取目标地址**。

为什么写指令不能先读？因为读 `$2007` 会推进 PPU 地址、读 `$2002` 会清除 vblank、
读 `$4015` 会清除 APU IRQ。如果 `STA $2007` 先做一次哑读，就会产生真实硬件上
不存在的副作用。

关键代码：

- [`ReadOperand`](../src/NesEmulator.Core/Cpu/Cpu6502.Execute.cs)
- [`ResolveAddress`](../src/NesEmulator.Core/Cpu/Cpu6502.Execute.cs)
- [`ReadPointer`](../src/NesEmulator.Core/Cpu/Cpu6502.Execute.cs)

## 5. 指令表

6502 的操作码并不是随机排列的。高 4 位和低 4 位分别编码操作类别与寻址方式，
形成著名的 16×16 矩阵。本项目把 256 项完整放在
[`OpcodeTable.cs`](../src/NesEmulator.Core/Cpu/OpcodeTable.cs)：

```csharp
table[0xAD] = O(0xAD, "LDA", Absolute, LDA, 4);
table[0xBD] = O(0xBD, "LDA", AbsoluteX, LDA, 4, pageCross: true);
```

`OpcodeInfo` 包含：

- 助记符；
- 寻址方式；
- 执行类别（`CpuOperation`）；
- 基础周期；
- 读操作是否可能因跨页 +1；
- 是否为官方指令。

执行器不需要 256 个分支，只需按“控制流 / 隐含 / 读 / 写 / 读-改-写”分类处理：

```text
取指 -> 查表 -> 按寻址方式取地址/值 -> 按操作类别执行 -> 返回周期
```

### 5.1 官方指令分组

| 类别 | 指令 |
|---|---|
| 传送 | LDA/LDX/LDY, STA/STX/STY, TAX/TAY/TSX/TXA/TXS/TYA |
| 算术 | ADC, SBC, CMP/CPX/CPY, INC/DEC, INX/INY/DEX/DEY |
| 逻辑 | AND, ORA, EOR, BIT |
| 移位 | ASL, LSR, ROL, ROR |
| 分支 | BCC/BCS/BEQ/BNE/BMI/BPL/BVC/BVS |
| 跳转/子程序 | JMP, JSR, RTS, RTI, BRK |
| 栈 | PHA/PHP/PLA/PLP |
| 标志 | CLC/SEC/CLI/SEI/CLV/CLD/SED |
| 其他 | NOP |

### 5.2 非官方指令

6502 的 256 个操作码中有大量未文档化但硬件会执行的组合指令。部分 NES 游戏和
测试 ROM 会使用它们。本项目实现了常见非官方指令：

| 指令 | 等价行为 |
|---|---|
| LAX | `A = X = mem` |
| SAX | `mem = A & X` |
| SLO | `ASL mem` 后 `ORA A` |
| RLA | `ROL mem` 后 `AND A` |
| SRE | `LSR mem` 后 `EOR A` |
| RRA | `ROR mem` 后 `ADC A` |
| DCP | `DEC mem` 后 `CMP A` |
| ISC | `INC mem` 后 `SBC A` |
| ANC | `A &= imm`，`C = N` |
| ALR | `A &= imm` 后 `LSR A` |
| ARR | `A &= imm` 后带进位右旋，特殊 V/C |
| AXS | `X = (A & X) - imm` |
| KIL/JAM | 停止 CPU 取指 |

`XAA/AHX/SHY/SHX/TAS/LAS` 等“不稳定指令”在不同芯片批次上行为不同。本项目采用
常见近似，并在文档中明确说明，不把它们当作精确硬件模型。

参考：[NESdev: CPU unofficial opcodes](https://www.nesdev.org/wiki/CPU_unofficial_opcodes)

## 6. 周期计数

6502 的周期不是“每条指令固定一个数”，而是由基础周期加额外周期组成：

### 6.1 读指令跨页

`LDA $12FF,X` 当 `X=1` 时有效地址 `$1300`，跨了页边界：

```text
基础 4 周期 + 1 周期页修正 = 5
```

只有**读**指令有这种惩罚。写指令 `STA $12FF,X` 固定 5 周期，因为写操作不会
提前读取错误地址再修正。

### 6.2 分支

```text
不跳      2 周期
跳了      3 周期
跳且跨页  4 周期
```

实现见：

```csharp
private int Branch(bool condition)
{
    sbyte offset = (sbyte)FetchByte();
    int cycles = 2;
    if (!condition) return cycles;
    cycles++;
    ushort target = (ushort)(PC + offset);
    if ((PC & 0xFF00) != (target & 0xFF00)) cycles++;
    PC = target;
    return cycles;
}
```

注意 `offset` 必须按**有符号 8 位**解释；目标地址以“分支指令之后”的 PC 为基准。

### 6.3 读-改-写

`ASL $1234,X`、`INC $10` 等固定周期，不做页修正。它们会读、改、写同一地址。

### 6.4 总周期

`Step()` 返回本条指令（或中断）的周期；`TotalCycles` 累加。PPU/APU 由
`NesConsole` 按这个数字推进。nestest 的 8,991 条日志同时校验寄存器和累计周期，
当前实现全部通过。

## 7. 中断与复位

6502 有三类中断入口：

| 类型 | 向量 | 触发方式 | 压栈 B |
|---|---|---|---|
| NMI | `$FFFA/$FFFB` | PPU vblank 的上升沿（不可屏蔽） | 0 |
| IRQ | `$FFFE/$FFFF` | 外部设备拉低 IRQ，且 I=0 | 0 |
| BRK | `$FFFE/$FFFF` | 执行 BRK 指令 | 1 |
| RESET | `$FFFC/$FFFD` | 复位 | 不压栈 |

中断响应序列（7 周期）：

```text
压入 PC 高字节
压入 PC 低字节
压入 P（NMI/IRQ 清 B，BRK 置 B）
设置 I=1
PC = 向量地址
```

实现：

```csharp
private int ServiceInterrupt(ushort vector, bool isBreak)
{
    Push((byte)(PC >> 8));
    Push((byte)(PC & 0xFF));

    byte pushedStatus = (byte)(_status | CpuFlags.Unused);
    pushedStatus = isBreak
        ? (byte)(pushedStatus | CpuFlags.Break)
        : (byte)(pushedStatus & ~CpuFlags.Break);

    Push(pushedStatus);
    SetFlag(CpuFlags.InterruptDisable, true);
    PC = Read16(vector);
    return 7;
}
```

### 7.1 NMI 是边沿触发

PPU 在 vblank 期间让 NMI 线保持高电平。CPU 只应在**上升沿**响应一次，而不是每个
周期都进入 NMI。`Step()` 用 `_previousNmiLine` 检测边沿：

```csharp
bool nmiEdge = NmiLine && !_previousNmiLine;
_previousNmiLine = NmiLine;
```

### 7.2 IRQ 是电平触发

只要 IRQ 线仍被拉低且 I=0，CPU 就会在每条指令边界再次进入中断。中断处理程序必须
写设备寄存器应答（例如读 `$4015`、写 MMC3 `$E000`）。

### 7.3 BRK 与 IRQ 的区别

- BRK 是 2 字节指令，PC 先 +2，再压栈；
- BRK 压入的 P 中 B=1；
- IRQ 不消耗操作码，PC 指向下一条指令，压入 P 中 B=0；
- 两者共用 `$FFFE` 向量。

`RTI` 从栈恢复 P 和 PC；它会把 B 位忽略（B 不是真实位）。

### 7.4 复位

```csharp
SP = 0xFD;
_status = I | Unused;
PC = Read16(0xFFFC);
TotalCycles = 7;
```

真实复位还会让 CPU 执行若干内部周期；本实现把初始周期设为 7，与 nestest 对拍约定一致。

## 8. 著名的 JMP 间接 bug

`JMP ($12FF)` 应该从 `$12FF/$1300` 读取目标地址。但 NMOS 6502 的硬件在计算高字节
地址时不会跨页，而是从 `$12FF/$1200` 读取：

```text
低字节 <- $12FF
高字节 <- $1200   （错误但真实）
```

代码保留了这个 bug：

```csharp
ushort highAddress = (ushort)((target & 0xFF00) | ((target + 1) & 0x00FF));
```

如果修掉它，依赖该 bug 的测试/游戏反而会失败。

## 9. 十进制模式

NES 的 2A03 去掉了十进制模式。即使 `D=1`，`ADC/SBC` 也按二进制运算。本项目始终
使用二进制算法，并在注释中说明。不要用标准 6502 的 BCD 逻辑来实现 NES。

## 11. 常见陷阱清单

- 零页索引忘记 `& 0xFF`；
- 分支偏移当成无符号；
- 写指令误读目标地址，触发 PPU/APU 副作用；
- `TAX/TAY` 写成 `A = X = A`（本项目早期就踩过）；
- 忘记读指令跨页 +1，或错误地给写指令加页修正；
- `JMP ($xxFF)` 跨页 bug 被“修复”；
- NMI 当电平触发，导致一帧进入多次；
- IRQ 没清 I 或在处理程序里没应答；
- BRK/IRQ 压栈的 B 位和 PC 值搞混；
- 把 NES 当标准 6502 实现 BCD。
