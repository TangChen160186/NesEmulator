# 10 · 已知限制、设计取舍与后续路线

> 一个诚实的模拟器应该明确说明“哪些地方是近似”。这一篇列出本项目的边界，
> 以及把“能学、能跑”提升到“高精度”需要做什么。

## 1. 总体设计取舍

本项目优先考虑：

1. **代码可读**：按 CPU/PPU/APU/卡带分层，注释解释硬件原因；
2. **可验证**：CPU 逐指令对拍、合成 ROM、自动化测试；
3. **零第三方依赖**：核心、CLI、桌面音频都用 .NET/Windows 自带能力；
4. **教学完整度**：从 ROM 解析到画面/声音/前端都有可运行代码。

代价是：

- 不是逐 dot 级精确；
- 不追求 100% 商业 ROM 兼容；
- 部分特殊 mapper/外设未实现；
- 音视频是近似模型。

## 2. CPU

### 已实现

- 所有官方指令；
- 常见非官方指令；
- 页跨界周期、分支周期；
- NMI/IRQ/BRK/复位；
- `JMP ($xxFF)` bug；
- nestest 8,991 条全部一致。

### 限制

- CPU 以“整条指令”为原子推进 PPU/APU，指令执行期间不会逐周期推进；
- 中断延迟、IRQ 采样点、DMA 与中断的交互是近似；
- 非官方不稳定指令（XAA/AHX/SHY/SHX/TAS/LAS）采用常见近似；
- 没有模拟 6502 的总线竞争/开总线细节；
- 没有 PAL 时钟（1.662607 MHz）。

**影响**：依赖精确中断时序、DMC DMA 停顿、RMW 总线行为的测试 ROM 可能失败。

## 3. PPU

### 已实现

- 寄存器、VRAM、调色板、名称表镜像；
- 背景 tile/属性/细滚动；
- 精灵 8×8/8×16、翻转、优先级；
- sprite 0 hit；
- vblank/NMI；
- 奇数帧跳 dot；
- 四屏 VRAM 内存。

### 主要近似

1. **背景按扫描线预取**
   每条可见扫描线开始时一次性构建 264 像素缓存。
   同一扫描线中途修改 `$2005/$2006` 不会立即影响本行剩余像素。
   真实 PPU 是逐 tile/逐 dot 取指，会有部分行生效的复杂效果。

2. **精灵在行首评估**
   真实 PPU 在 dot 65-256 做二次 OAM 评估，OAMADDR/寄存器写入的时机有影响。
   本实现行首一次性评估，绝大多数游戏不受影响。

3. **sprite overflow 简化**
   第 9 个候选精灵直接置位，不模拟 2C02 的评估 bug。

4. **vblank/NMI 读写竞争**
   读取 `$2002` 对 NMI 的抑制、$2000 在 vblank 中使能 NMI 的精确时序未建模。

5. **$2007 渲染中访问**
   采用线性 +1/+32 自增近似，没有实现渲染时 coarse X/Y 的复杂递增。

6. **精灵 0 hit 的部分细节**
   不模拟预渲染行、裁剪窗口变化、精确像素优先级的全部硬件行为。

7. **色彩**
   64 色表是社区常用近似；灰度/强调是简化模型，不是 NTSC 信号仿真。

8. **Odd frame skip**
   已实现基本跳 dot，但帧起点/奇偶相位可能与真实硬件差一帧。

**影响**：`ppu_vbl_nmi`、`sprite_overflow_tests`、部分光栅 trick 会失败。

## 4. APU

### 已实现

- Pulse 1/2、Triangle、Noise、DMC；
- 包络、长度、扫频、线性计数器；
- 4/5 步帧序列器；
- 44.1 kHz 单声道 PCM；
- 帧 IRQ、DMC IRQ。

### 限制

- DMC 不模拟抢占总线导致的 CPU 停顿；
- 5 步模式写入后的时钟延迟是近似；
- 混音使用线性近似，不是精确非线性 DAC；
- 没有 PAL 周期表；
- 没有扩展音频（VRC6、Namco 163、FDS、MMC5）；
- 音频输出依赖 Windows `waveOut`，延迟约 93 ms。

**影响**：`apu_tests`/`dmc_tests` 的严格时序项可能失败；音乐通常可听。

## 5. 卡带/Mapper

### 已实现

- iNES 1.0、常见 NES 2.0；
- mapper 0/1/2/3/4；
- CHR-RAM、PRG-RAM、电池存档；
- 四屏；
- MMC1 串行写、MMC3 bank + 扫描线 IRQ。

### 限制

- 没有 mapper 5、7、9、10、16、18、19、21、23、24、25、26、30、69、85 等；
- MMC3 IRQ 用 dot 260 近似 A12 上升沿，没有 A12 滤波/延迟；
- MMC3 rev A/B 差异未区分；
- MMC1 只实现常见 SxROM 行为；
- UxROM 512 KB 只有部分行为，Owlia 等 UNROM-512 游戏可能无法启动；
- 没有 bus conflicts 的完整板级模型（UxROM 仅在 ≤256 KB 时模拟）；
- 没有 FDS、扩展音频、光枪、Four Score、麦克风等外设；
- trainer 被跳过；
- PRG-RAM 初始值固定为 0，真实硬件不确定；
- 没有存档状态/回放。

## 6. 前端

- 只支持 Windows（WinForms）；
- 键盘映射固定，不支持手柄；
- 没有金手指、倒带、即时存档、调试器；
- 音频使用 `waveOut`，延迟固定；
- 截图是当前帧缓冲，不包含 CRT 滤镜；
- 没有自动更新/ROM 库管理。

## 7. 兼容性观察

本机测试过的 homebrew：

| ROM | 结果 | 备注 |
|---|---|---|
| pong1k | 正常 | NROM/CHR-RAM |
| robotfindskitten | 正常 | NROM/32 KB PRG |
| Nova the Squirrel | 正常 | MMC1/256 KB/CHR-RAM |
| Twin Dragons | 正常显示标题 | UxROM/256 KB |
| Miedow、Robo-Ninja Climb | 正常显示标题 | CNROM |
| Indivisible on NES | 正常显示标题 | MMC3/128 KB |
| The Legends of Owlia、Nomolos | 启动失败/画面异常 | 512 KB UNROM-512，接近 mapper 30 |

没有测试商业 ROM。请勿在 issue/讨论中上传商业 ROM；用最小复现或自制 ROM 描述问题。

## 8. 后续路线（按收益排序）

### P0：兼容性

1. **Mapper 30 / UNROM-512**
   - 5 位 bank；
   - CHR-RAM banking；
   - 单屏/镜像控制；
   - Flash 寄存器语义。
2. **更多 mapper**
   - MMC5、VRC6、Namco 163（如果要做扩展音频）；
   - mapper 7/9（AxROM/MMC2）。
3. **DMC DMA 停顿**
   - 在 APU 取样本时向 CPU 请求停顿；
   - 与 OAM DMA 叠加。

### P1：时序精度

1. 把 CPU 改为按周期步进；
2. PPU 改为逐 tile/逐 dot 取指，使用移位寄存器；
3. 实现 sprite overflow bug；
4. 实现 `$2002/$2005/$2006` 读写竞争；
5. MMC3 A12 滤波/IRQ 延迟；
6. 精确奇数帧相位；
7. PAL 支持。

### P2：工具与体验

1. 调试器（CPU/PPU/APU 状态、VRAM/OAM 查看、断点、反汇编）；
2. 即时存档/读档、倒带；
3. 手柄支持；
4. 音视频设置（缓冲、滤镜、NTSC）；
5. ROM 信息/数据库；
6. 自动测试更多 homebrew ROM。

### P3：高级硬件

- FDS；
- 扩展音频；
- Four Score/光枪/麦克风；
- 真机烧录辅助。

## 9. 如何判断一个 bug 是否“值得修”

先分类：

1. **CPU 语义/周期错误**：优先修，nestest 能否覆盖？
2. **PPU 寄存器/VRAM 错误**：优先修，截图/测试 ROM 能否复现？
3. **Mapper bank/IRQ 错误**：优先修，合成 ROM 能否验证？
4. **dot 级时序差异**：记录为已知限制，除非目标游戏依赖；
5. **音频混音差异**：通常不影响游戏逻辑，低优先级；
6. **前端体验**：按用户需求排优先级。

## 10. 对外说明模板

如果你要发布这个项目，建议在 README/Release 中明确写：

> 这是一个教学型 NES 模拟器，CPU 通过 nestest，支持 mapper 0-4 和 NTSC。
> PPU 采用扫描线级背景预取，未实现 dot 级读写竞争、sprite overflow bug、
> DMC DMA 停顿和 PAL。它适合学习与运行多数 NROM/MMC1/UxROM/CNROM/MMC3 游戏，
> 不保证商业 ROM 100% 兼容。仓库不包含商业 ROM。

这样既诚实，也能让使用者建立正确预期。
