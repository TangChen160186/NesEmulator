# 06 · 源码导读与扩展指南

> 这一篇回答三个问题：代码从哪里读起？运行时谁调用谁？如果想继续加功能，应该改哪里？

## 1. 解决方案结构

```text
NesEmulator.slnx
├─ src/NesEmulator.Core        # 模拟器核心，无 UI 依赖
├─ src/NesEmulator.Cli         # 无头运行器 + PNG 截图
├─ src/NesEmulator.Desktop     # WinForms + waveOut 音频
├─ tests/NesEmulator.Tests     # 自包含测试运行器
└─ tools/HelloNes.Builder      # 迷你 6502 汇编器 + 演示 ROM
```

### 1.1 Core 目录

| 路径 | 作用 |
|---|---|
| `Cartridges/` | iNES 头、ROM 加载、卡带抽象、mapper 0-4 |
| `Cpu/` | 6502 寄存器/中断、256 项操作码表、执行器 |
| `Ppu/` | 2C02 寄存器、VRAM、逐 dot 时序、背景/精灵渲染、调色板、帧缓冲 |
| `Apu/` | 2A03 帧序列器、五个声道、混音、环形音频缓冲 |
| `Bus/` | CPU 地址解复用、OAM DMA、中断线汇总 |
| `Input/` | 标准手柄的选通与串行读取 |
| `Emulation/` | `NesConsole`：把上述部件组装并同步时钟 |

## 2. 运行时调用链

### 2.1 创建主机

```text
InesRomLoader.Load(path)
  -> InesHeader.Parse(header)
  -> new Cartridge(header, prg, chr)
       -> new Mapper000/001/...
  -> new NesConsole(cartridge)
       -> new Controller ×2
       -> new NesBus(cartridge, ...)
            -> new Ppu2C02(cartridge)
            -> new Apu2A03(Read)   // DMC 用 CPU 总线读采样
       -> new Cpu6502(bus)
       -> Reset()
```

### 2.2 运行一帧

```text
NesConsole.RunFrame()
  while PPU.FrameCount < target:
      StepInstruction()
          Bus.CpuCycle = CPU.TotalCycles
          cycles = CPU.Step()
              CPU 读/写 -> NesBus -> RAM/PPU/APU/卡带
          dma = Bus.TakeDmaStallCycles()
          CPU.AddStallCycles(dma)
          Bus.Tick(cycles + dma)
              PPU.Step(×3)
              APU.Step(×1)
          CPU.NmiLine = PPU.NmiOutput
          CPU.IrqLine = Bus.IrqLine
```

### 2.3 CPU 执行一条指令

```text
Cpu6502.Step()
  if NMI 上升沿 -> ServiceInterrupt(0xFFFA)
  else if IRQ 且 I=0 -> ServiceInterrupt(0xFFFE)
  else:
      opcode = Read(PC++)
      info = OpcodeTable[opcode]
      cycles = Execute(info)
          switch 控制流/隐含/读/写/RMW
          ReadOperand 或 ResolveAddress
          ExecuteRead/Store/ReadModifyWrite
```

### 2.4 PPU 输出一个像素

```text
Ppu2C02.Step()
  扫描线起点：BuildBackgroundLine() + EvaluateSpritesForScanline()
  dot 1-256：RenderPixel(x)
      background = _backgroundLine[x + _fineX]
      sprite = _spriteLine[x]
      sprite 0 hit 检查
      优先级合成
      查 palette RAM -> PpuPalette -> FrameBuffer
```

## 3. 推荐阅读顺序

### 第一遍：只追一条路径

1. `NesConsole.RunFrame`
2. `NesBus.Tick`
3. `Cpu6502.Step`
4. `Cpu6502.Execute` 的 `LDA` 路径
5. `NesBus.Read` 的 RAM 分支

读完后你应该能回答：CPU 读一个字节时，谁决定了它来自 RAM/PPU/卡带？

### 第二遍：PPU

1. `Ppu2C02.WriteRegister` 的 `$2006/$2007`
2. `Ppu2C02.ReadVram/WriteVram`
3. `BuildBackgroundLine`
4. `RenderPixel`
5. 调色板与镜像

### 第三遍：中断与整机

1. `Ppu2C02.Step` 中的 vblank/NMI
2. `ServiceInterrupt`
3. `NesConsole.StepInstruction` 中的 NMI 线采样
4. `Mapper004.OnScanline`
5. `NesBus.IrqLine`

### 第四遍：卡带

1. `InesHeader.Parse`
2. `InesRomLoader.Load`
3. `Mapper000` → `Mapper002` → `Mapper001` → `Mapper004`

## 4. 调试技巧

### 4.1 先确认 CPU

`nestest` 是最高性价比的验证：8,991 条指令同时检查寄存器、标志、栈指针和周期。
如果 CPU 不对，先不要怀疑 PPU。

### 4.2 用自制 ROM 隔离 PPU

`HelloNes.Builder` 生成的 ROM 只依赖 NROM、CHR-ROM、NMI、OAM DMA 和调色板。
如果它不正常，问题通常在 PPU/总线，而不是复杂 mapper。

### 4.3 无头截图

```powershell
dotnet run --project src/NesEmulator.Cli -- rom.nes --frames 120 --screenshot frame.png
```

不需要打开窗口就能检查画面；配合逐步增加 `--frames` 可以看启动过程。

### 4.4 检查 CPU 卡在哪

- 在 `NesConsole.StepInstruction` 里临时打印 `PC`、`A/X/Y/P/SP`；
- 在 `Cpu6502.Execute` 里按操作码打印；
- 在 `NesBus.Read/Write` 里过滤 `$2000-$4017`，观察 PPU/APU 访问序列；
- 用 `Cpu6502.CaptureState()` / `RestoreState()` 做最小复现。

### 4.5 检查 PPU 内部状态

- 打印 `v/t/x/w`、`Scanline/Cycle`；
- 打印 `_paletteRam` 与 `_nameTableRam`；
- 检查 `Ppu.FrameBuffer.Pixels` 的特定坐标；
- 用 `$2002` 的 vblank/sprite0 位判断时序。

## 5. 扩展方向

### 5.1 新增 Mapper

参考 [`05-卡带与Mapper.md`](05-卡带与Mapper.md) 第 12 节。最小步骤：

```csharp
public sealed class Mapper005 : Mapper
{
    public override string Name => "MMC5";
    public override byte ReadPrg(ushort address) { ... }
    public override void WritePrg(ushort address, byte value, long cpuCycle) { ... }
    public override byte ReadChr(ushort address) { ... }
}
```

然后在 `MapperFactory` 注册，并写测试。

### 5.2 存档状态（Save State）

需要捕获：

- CPU：`A/X/Y/S/P/PC/Cycles/Jammed`（已有 `CpuState`）；
- CPU RAM：2 KB；
- PPU：`v/t/x/w`、控制/掩码/状态、OAM、VRAM、调色板、当前扫描线/周期；
- APU：所有声道内部计数器、帧序列器、当前样本累加器；
- 卡带：PRG-RAM、mapper 所有寄存器；
- 输入：手柄状态。

建议给每个组件加 `CaptureState()` / `RestoreState()`，用版本号封装成二进制或 JSON。
注意：音频环形缓冲不应存档。

### 5.3 PAL 支持

需要改：

- CPU 时钟 1.662607 MHz；
- PPU 每帧 312 条扫描线、50 Hz；
- APU 噪声/DMC 周期表不同；
- 帧率/音频采样换算；
- 部分游戏有 PAL/NTSC 两套代码。

可以引入 `NesRegion` 配置，而不是硬编码常量。

### 5.4 更精确的 PPU

当前背景按扫描线预取、PPU 以指令为单位被推进。要提升到 dot 级：

1. 把 CPU 改为按周期步进（每个总线访问插入时钟）；
2. PPU 内部实现 16 位移位寄存器、逐 tile 取指、二次 OAM；
3. 精确模拟 `$2002/$2005/$2006` 的读写竞争；
4. sprite overflow bug；
5. MMC3 A12 滤波与 IRQ 延迟；
6. DMC DMA 的 CPU 停顿和总线冲突。

这是“从能玩到高精度”的分水岭，工作量远大于当前实现。

### 5.5 DMC DMA 停顿

DMC 每次取字节会暂停 CPU 若干周期。可以在 `DmcChannel` 取样本时记录
“需要停顿的周期”，由 `NesConsole` 加到 CPU 时钟。难点是与 CPU 当前指令的
对齐，以及和 OAM DMA 的交互。

### 5.6 前端增强

- 手柄/键盘映射配置；
- 即时存档/读档；
- 金手指；
- 音频音量/缓冲延迟设置；
- 视频滤镜（扫描线、NTSC）；
- 调试器（寄存器、内存、反汇编、断点、图层查看）。

反汇编器可以基于 `OpcodeTable` 很容易地实现，CLI 也可以增加 `--trace`。

## 6. 代码风格与注释

- 核心代码使用中文 XML 注释，解释“为什么”，而不是重复“做了什么”；
- 硬件常量尽量命名（`DotsPerScanline`、`FrameQuarter1`）；
- 时序/边界处写清楚取舍；
- 测试用合成 ROM，不依赖商业 ROM；
- 新功能必须能通过现有测试，并补充对应测试。

## 7. 性能参考

本机（Windows，.NET 10/11）无头运行：

- Debug 构建约 85-110 FPS；Release 构建的简单 ROM 可达数百 FPS（演示 ROM 约 450 FPS）；
- 桌面端按 60.0988 Hz 节流，稳定 60.0 FPS，音频线程独立；
- 一帧约 30,000 条 CPU 指令 / 89,000 个 PPU dot / 735 个音频样本。

如果性能不足，优先考虑：

- Release 构建；
- 减少每像素的查询/虚调用；
- 用数组缓存 nametable/pattern；
- 不要在主循环分配对象。
