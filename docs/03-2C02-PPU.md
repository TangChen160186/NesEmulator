# 03 · 2C02 PPU：图块、滚动、精灵与 NMI

> PPU（Picture Processing Unit）是 NES 画面真正的生产者。CPU 只负责在合适的时机
> 改寄存器；PPU 按自己的 5.37 MHz 时钟逐 dot 输出扫描线。

## 1. PPU 的内存与画面模型

PPU 不存“像素”，而存“图块 + 名称表 + 调色板”：

```text
pattern table ($0000-$1FFF)
  两个 4 KB 表，每个 256 个 8×8 tile
  每个 tile 16 字节：8 字节低位平面 + 8 字节高位平面
        │
        ▼
name table ($2000-$2FFF)
  32×30 个 tile 编号（960 字节）
  + 64 字节属性表（每 16×16 像素区域选一个 4 色调色板）
        │
        ▼
palette RAM ($3F00-$3F1F)
  32 字节，每个字节是 6 位 NES 颜色号
        │
        ▼
OAM（64 个精灵）
  Y, tile, attribute, X
```

### 1.1 Pattern table（图块）

每个 8×8 tile 由两个位平面组成：

```text
低平面字节：  1 0 1 0 1 0 1 0
高平面字节：  0 0 1 1 0 0 1 1
合成颜色号：  1 0 3 2 1 0 3 2
```

颜色号 0-3 分别对应调色板中的第 0-3 项。背景颜色 0 透明（显示 backdrop），
精灵颜色 0 也透明。

tile 在 pattern table 中的地址：

```text
address = patternBase + tileIndex * 16 + row
low  = read(address)
high = read(address + 8)
color = ((low >> bit) & 1) | (((high >> bit) & 1) << 1)
bit = 7 - x   // MSB 是最左边的像素
```

### 1.2 Name table（名称表）

一个名称表 1 KB：

- 960 字节 tile 编号，按 32×30 排列；
- 64 字节属性表，位于 `$23C0`。

屏幕 256×240 = 32×30 个 8×8 tile。名称表不存颜色，只存“用哪个 tile”。

属性表每个字节管理 4×4 个 tile（32×32 像素），再分成四个 2×2 tile 象限，
每个象限 2 位，选择 4 个背景调色板之一：

```text
属性字节：  bits 7-6 | bits 5-4
            bits 3-2 | bits 1-0
```

本项目的取值方式：

```csharp
int shift = ((coarseY & 0x02) << 1) | (coarseX & 0x02);
int paletteBase = (attribute >> shift) & 0x03;
```

### 1.3 调色板

32 字节：

- `$3F00-$3F0F`：4 个背景调色板，每个 4 色；
- `$3F10-$3F1F`：4 个精灵调色板，每个 4 色；
- `$3F00`：全局背景色（backdrop）；
- `$3F10/$3F14/$3F18/$3F1C` 镜像到 `$3F00/$3F04/$3F08/$3F0C`。

**关键概念**：调色板 RAM 里存的是 6 位 NES 颜色号（0-63），不是 RGB。
最终 RGB 由电视制式和 PPU 的模拟输出决定。本项目用
[`PpuPalette.cs`](../src/NesEmulator.Core/Ppu/PpuPalette.cs) 中的 2C02 近似调色板。

> 实现时曾经踩过一个坑：背景合成得到的是“调色板 RAM 地址 0-31”，
> 必须再查一次 `_paletteRam` 才能得到 6 位颜色号。直接把 0-31 当地址传给
> RGB 表会得到完全错误的颜色。

### 1.4 OAM（精灵内存）

64 个精灵 × 4 字节：

| 偏移 | 含义 |
|---|---|
| +0 | Y 坐标（实际显示从 Y+1 开始） |
| +1 | tile 编号 |
| +2 | 属性：bit7 垂直翻转、bit6 水平翻转、bit5 优先级、bit1-0 调色板 |
| +3 | X 坐标 |

CPU 不能直接访问 OAM，只能：

- 写 `$2003` 设置 OAMADDR；
- 写 `$2004` 逐个写；
- 写 `$4014` 触发 OAM DMA，一次复制 256 字节。

绝大多数游戏在 vblank 中用 DMA 更新 OAM。

## 2. PPU 寄存器

CPU 通过 `$2000-$2007` 访问 PPU：

| 地址 | 名称 | 读/写 | 作用 |
|---|---|---|---|
| `$2000` | PPUCTRL | 写 | NMI 使能、精灵大小、pattern table 选择、VRAM 增量、名称表选择 |
| `$2001` | PPUMASK | 写 | 灰度、左 8 像素裁剪、背景/精灵使能、RGB 强调 |
| `$2002` | PPUSTATUS | 读 | vblank、sprite 0 hit、overflow、开总线 |
| `$2003` | OAMADDR | 写 | OAM 地址 |
| `$2004` | OAMDATA | 读写 | OAM 数据 |
| `$2005` | PPUSCROLL | 写 | 滚动，两次写入 |
| `$2006` | PPUADDR | 写 | VRAM 地址，两次写入 |
| `$2007` | PPUDATA | 读写 | VRAM 数据，带读缓冲 |

### 2.1 PPUCTRL（$2000）

```text
bit 7  NMI 使能
bit 6  master/slave（通常 0）
bit 5  精灵高度：0=8×8，1=8×16
bit 4  背景 pattern table：0=$0000，1=$1000
bit 3  精灵 pattern table：0=$0000，1=$1000（8×8 时）
bit 2  VRAM 地址增量：0=+1，1=+32
bit 1-0 名称表选择（写入 t 的 bit 10-11）
```

### 2.2 PPUMASK（$2001）

```text
bit 7  强调蓝
bit 6  强调绿
bit 5  强调红
bit 4  显示精灵
bit 3  显示背景
bit 2  左 8 像素显示精灵
bit 1  左 8 像素显示背景
bit 0  灰度
```

### 2.3 PPUSTATUS（$2002）

```text
bit 7  vblank
bit 6  sprite 0 hit
bit 5  sprite overflow
bit 4-0 开总线
```

读取 `$2002` 会：

- 清除 vblank 标志；
- 清除写入锁存 `w`；
- 可能抑制本帧 NMI（时序竞争；本实现为简化模型）。

### 2.4 PPUDATA（$2007）的读缓冲

VRAM 读取不是立即返回：

```csharp
if (address >= 0x3F00) {
    result = ReadPalette(address);
    _readBuffer = ReadVram(address - 0x1000);
} else {
    result = _readBuffer;
    _readBuffer = ReadVram(address);
}
```

调色板读取是即时的，但读缓冲会被填成“地址 - $1000”处的名称表字节。
这是很多游戏初始化时“读一次丢弃”的原因。

## 3. Loopy 滚动寄存器

PPU 内部有一组 15 位寄存器：

```text
v:  yyy NN YYYYY XXXXX
    │   │  │     └──── coarse X (0-31)
    │   │  └────────── coarse Y (0-29/31)
    │   └───────────── nametable 选择 (0-3)
    └───────────────── fine Y (0-7)

t:  同 v，CPU 写 $2005/$2006 时的暂存值
x:  fine X (0-7)
w:  $2005/$2006 的双写翻转
```

### 3.1 $2005 写入

第一次：

```text
t.coarseX = value >> 3
fineX     = value & 7
```

第二次：

```text
t.coarseY = (value & 0xF8) >> 3
t.fineY   = value & 7
```

### 3.2 $2006 写入

第一次：高 6 位写入 `t` 的 bit 8-13；
第二次：低 8 位写入 `t`，同时 `v = t`。

### 3.3 渲染中的复制

```text
dot 256        v.coarseY++（带 fineY/29 回绕）
dot 257        v 的水平位 <- t 的水平位
pre-render 280-304  v 的垂直位 <- t 的垂直位
```

此外，在取背景 tile 时，`v.coarseX` 递增，31→0 时横向名称表翻转。

这套机制让游戏可以：

- 在 vblank 里设置 `t`，在下一帧开始时自动装入 `v`；
- 在扫描线中途修改 `v`/`t` 制作状态栏、分屏、波浪效果（本实现只支持逐行）。

## 4. 一帧的渲染流程

```text
扫描线 0-239：
  dot 1-256    背景像素 + 精灵像素输出
  dot 256      coarse Y++
  dot 257      水平滚动复制
  dot 257-320  精灵评估/取指
  dot 321-336  预取
扫描线 240：post-render
扫描线 241：vblank 开始，NMI
扫描线 261：pre-render，清 vblank/sprite0/overflow
```

### 4.1 背景

对每个 tile，PPU 依次取：

1. 名称表字节（tile 编号）；
2. 属性表字节（调色板）；
3. pattern 低位平面；
4. pattern 高位平面。

然后通过移位寄存器输出 8 个像素。细滚动 `fineX` 会让像素在相邻 tile 之间跨界，
所以一条 256 像素的扫描线实际可能涉及 33 个 tile。

本项目的实现是“扫描线预取”：

- 在每条可见扫描线开始时，根据 `v` 的 coarse X/Y、fineY 预取 33 个 tile；
- 生成 264 个像素的调色板地址缓存；
- 输出时取 `backgroundLine[x + fineX]`。

优点：代码直白、细滚动正确、逐行 raster 效果可用。
限制：同一扫描线中途修改 `$2005/$2006` 不会立即改变本行剩余像素；真实 PPU 会
影响后续 tile 的取指。详见 [已知限制](10-已知限制与后续路线.md)。

### 4.2 精灵

精灵评估（sprite evaluation）：

- 扫描当前 OAM 的 64 个精灵；
- Y 范围覆盖当前扫描线的精灵进入“次级 OAM”；
- 最多 8 个；
- 第 9 个会置 sprite overflow。

每个精灵的像素：

```text
row = scanline - (spriteY + 1)
if (attr & 0x80) row = height - 1 - row
if (attr & 0x40) bit = column else bit = 7 - column
```

8×16 精灵：

- tile 的 bit0 选 pattern table；
- tile 编号的低位被忽略；
- 先显示 tile，再显示 tile+1。

优先级：

- 同一像素有多个精灵时，OAM 中靠前的精灵优先；
- 属性 bit5=0：精灵在背景前；
- 属性 bit5=1：精灵在背景后（背景不透明时被遮住）。

### 4.3 Sprite 0 hit

条件：

- 背景和精灵都开启；
- sprite 0 在该像素不透明；
- 背景在该像素不透明；
- `x != 255`；
- 左 8 像素裁剪没有把任一方隐藏。

满足时置 `$2002` bit6。它常用于分屏：游戏在 sprite 0 命中后等待，然后修改滚动。

本实现通过 `_spriteZeroOpaque[256]` 记录 sprite 0 的不透明像素，在合成阶段置位。

### 4.4 Sprite overflow

真实 2C02 的 overflow 评估有一个著名 bug：当一行超过 8 个精灵时，硬件可能把
非精灵数据当成精灵继续扫描，导致某些情况下 overflow 不置位或置位错误。

本项目采用简化模型：发现第 9 个候选精灵就置 bit5，不做 bug 模拟。对大多数游戏
足够，但专门的 sprite overflow 测试 ROM 会失败。

## 5. VBlank、NMI 与 CPU 的协作

```text
扫描线 241 dot 1：
    status.vblank = 1
    NMI = vblank && PPUCTRL.bit7

扫描线 261 dot 1：
    status.vblank = 0
    status.sprite0 = 0
    status.overflow = 0
```

NMI 是**边沿触发**：CPU 在 vblank 开始时进入一次 NMI 处理程序。处理程序通常：

1. 保存寄存器；
2. 更新 OAM（DMA）；
3. 更新滚动；
4. 更新音乐；
5. 恢复寄存器并 `RTI`。

读取 `$2002` 会清除 vblank，也会让 NMI 线变低。真实硬件在 vblank 开始附近读
`$2002` 可能抑制 NMI，这是一个时序竞争；本实现只在指令边界采样，未精确建模。

## 6. 名称表镜像

主机只有 2 KB CIRAM，但有四个逻辑名称表。镜像方式：

| 模式 | 逻辑表 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| Horizontal | A | A | B | B |
| Vertical | A | B | A | B |
| SingleScreenLower | A | A | A | A |
| SingleScreenUpper | B | B | B | B |
| FourScreen | A | B | C | D（需要 4 KB） |

实现：

```csharp
return Mirroring switch
{
    Mirroring.Vertical => logicalIndex & 1,
    Mirroring.Horizontal => logicalIndex >> 1,
    Mirroring.SingleScreenLower => 0,
    Mirroring.SingleScreenUpper => 1,
    Mirroring.FourScreen => logicalIndex & 3,
    _ => logicalIndex & 1,
};
```

横向卷轴游戏通常用 Vertical 镜像，因为它让逻辑表 0/1 指向不同物理表；
纵向卷轴游戏通常用 Horizontal。

## 7. 灰度与强调

- 灰度（PPUMASK bit0）：把 6 位颜色号与 `$30` 相与，只保留 4 个灰度级；
- 强调（bit5-7）：改变 RGB 通道比例。本项目用简单的亮度近似，不是精确的
  NTSC 信号模型。

## 9. PPU 常见陷阱

1. 把“调色板 RAM 地址”直接当“NES 颜色号”；
2. `$2007` 读缓冲忘记实现；
3. 调色板镜像 `$3F10 -> $3F00` 忘记；
4. 精灵 Y 坐标实际从 `Y+1` 开始；
5. 8×16 精灵忘记忽略 tile 低位、切换 pattern table；
6. 左 8 像素裁剪分别由 PPUMASK bit1/bit2 控制；
7. sprite 0 hit 在 `x=255` 不触发；
8. 读取 `$2002` 忘记清 `w` 和 vblank；
9. 名称表镜像方向写反；
10. NMI 当电平触发；
11. 在可见扫描线中途写 VRAM/OAM，真实硬件有复杂行为；
12. 忘记奇数帧跳 dot，长期帧率略偏。
